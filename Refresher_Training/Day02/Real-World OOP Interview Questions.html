⚡ Real-World OOP Interview Questions

C# Scenarios for Junior to Architect Roles
🔹 Level 1: Foundational

1. The "Payment Processor"

Scenario: Fintech app supporting Stripe, PayPal, and Razorpay with different charge methods.
Question: How do you design this so the Checkout service is decoupled?
Solution: Use an IPaymentGateway interface. Each gateway implements it. Checkout service takes IPaymentGateway via Dependency Injection.

2. The "Employee Management"

Scenario: Base Employee class with CalculatePay(). Derived FullTimeEmployee and InternEmployee.
Question: Prevent inheritance from InternEmployee. Allow overriding CalculatePay with a default base implementation.
Solution: Mark InternEmployee as sealed. Use virtual in base and override in derived classes.

3. The "E-commerce Discount"

Scenario: Black Friday sales. Need flexible discounts without modifying Product class.
Question: Implement a discount strategy using the Strategy Pattern.
Solution: IDiscountStrategy interface with ApplyDiscount method. Cart receives the strategy. No switch statements inside Product.
🔸 Level 2: Intermediate

4. The "Logging Library"

Scenario: Need a single logger instance to prevent file locking.
Question: Implement thread-safe Singleton. Why not a static class? Limitation?
Solution: Use Lazy<T>. Static classes can't implement interfaces or be mocked. Limitation: introduces global state and hurts testability.

5. The "Report Generator"

Scenario: Reports in PDF, Excel, CSV. Steps: Fetch, Format, Save. Format differs per format.
Question: Design to prevent code duplication.
Solution: Abstract base class ReportGenerator with Template Method GenerateReport(). FormatData() is protected abstract.

6. The "UI Controls" (LSP)

Scenario: Square inherits from Rectangle. Setting Width also sets Height.
Question: Is this good design? How does it break Liskov Substitution?
Solution: Bad design. If a method expects a Rectangle and sets Width=10; Height=5;, a Square will fail (Height becomes 10). Use IShape interface instead.
🔹 Level 3: Advanced (Senior/Architect)

7. The "Plug-in Architecture"

Scenario: Load unknown plugins from .dlls at runtime.
Question: Design the contract and discovery mechanism.
Solution: Define IPlugin in a shared DLL. Use Assembly.LoadFile, reflection (IsAssignableFrom), and Activator.CreateInstance.

8. The "Expensive Database Call"

Scenario: Customer.OrderHistory is expensive to fetch. Load only when accessed.
Question: Implement lazy loading using a proxy.
Solution: Use Lazy<List<Order>> backing field. Initialize in constructor with a database delegate.

9. The "Cross-Cutting Concern"

Scenario: Need to add Encryption, Compression, and Buffering to a Stream.
Question: How does the Decorator pattern prevent class explosion?
Solution: Each decorator takes a Stream in its constructor. Instantiate as: new EncryptionStream(new CompressionStream(new FileStream())).

10. The "Immutable DTO"

Scenario: Microservice event OrderSubmittedEvent must be thread-safe and immutable.
Question: Compare record vs class (private set) vs readonly struct.
Solution: Records are best for DTOs (value equality). readonly struct is best for high-performance (no GC pressure). Use struct if publishing millions of events/sec.
⚠️ Level 4: The "Gotchas"

11. Constructor Chaos

Scenario: Derived d = new Derived("test");
Question: What constructor order executes?
Answer: Base (parameterless) then DerivedString. The base(10) from the other constructor is not called.

12. new vs override

Scenario: A obj = new C(); obj.Show();
Question: What prints? A, B, or C?
Answer: B. The new keyword hides the implementation but doesn't override it. The virtual table still points to the last override (B).
